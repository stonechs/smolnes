# smolnes 按扫描线渲染改造说明

## 目标

以 V1.1 的 Win32/GDI 版本为起点，参考 `D:\2026work\jsneslite\src\ppu.js` 的扫描线渲染组织方式，降低当前逐像素扫描 OAM 的开销。保留 V1.1 版本与快照不变；新版本使用独立构建脚本、输出目录和归档目录。

## 设计约定

- CPU 仍按现有方式一次执行一条指令，然后推进该指令对应的 PPU 周期。
- PPU 的 dot、scanline、VBlank/NMI、MMC3 IRQ 和现有 60Hz 帧节奏保留。
- 画面输出改为扫描线组织：背景先生成当前行像素，精灵按行筛选后参与该行合成。
- 采用 jsnes-lite 的实用兼容度，不移植 jsnes 的逐总线周期 CPU/PPU 调度框架。
- 每个实现阶段都单独编译、运行 `pig.NES` 冒烟检查，并保存不可覆盖的阶段快照和 SHA-256 清单。

## 修改阶段

### 阶段 0：冻结基线（已完成）

- 保存当前 V1.1 源码、构建脚本、正式 EXE 和基线冒烟记录。
- 验证基线输入文件哈希，确保后续改动不覆盖 V1.1。

### 阶段 1：按扫描线筛选精灵（已完成）

- 增加当前扫描线的精灵候选缓存。
- 每行按 OAM 顺序筛选垂直范围内的前 8 个精灵，供像素合成使用。
- 像素级颜色合成和 Sprite 0 hit 的 dot 时序暂时保留；减少每个可见像素重复遍历 64 个 OAM 项的操作。
- 验证无精灵背景、精灵输出、8 精灵上限，以及 `pig.NES` 窗口/画面/关闭流程。

### 阶段 2：背景扫描线缓冲（已完成）

- 添加 256 像素背景颜色与调色板行缓冲，由现有逐 dot 背景移位管线填充。
- 保留图块/属性/滚动/图案读取的 dot 时点；缓存当前 dot 的背景像素与调色板信息，供精灵合成使用。
- 保留必要的 PPU 地址递增、扫描线位置和 mapper IRQ 更新；避免让显示输出路径重复执行背景像素转换。
- 验证背景颜色、水平滚动、透明背景色及 `pig.NES` 冒烟表现。

### 阶段 3：扫描线合成与显示（已完成）

- 在扫描线开始时按 OAM 优先级把前 8 个精灵的非透明像素预解码到 256 像素行图；背景仍按 dot 采样，每个 dot 从缓存精灵行取样并合成后写入帧缓冲。
- 保持窗口重绘只显示已完成帧缓冲，不在 WM_PAINT 中运行模拟逻辑。
- 移除每个像素反复遍历候选精灵及读取 CHR 位平面的路径；保留 Sprite 0 hit 的 dot 时点。
- 运行全部冒烟检查，检查 DLL 导入和帧率诊断，并归档最终 V1.2 候选。

## 风险与边界

- 行级图像生成是精度/复杂度折中，不等同于逐 PPU 点的硬件像素流水线。
- CPU 指令之间仍可写 PPU 寄存器；本改造沿用 jsnes-lite 的扫描线模型，不承诺精确复现所有同一扫描线内的栅格效果。
- 精灵筛选将实现硬件可见的每行 8 个精灵上限，超出部分画面可能与当前未限数的行为不同。
- `pig.NES` 冒烟验证只能确认启动与基础画面，不代表广泛 ROM 兼容性。

## 性能测量约定

- 每个阶段以冻结的 V1.1 和上一阶段候选作对照；相同机器、`pig.NES`、编译器、编译参数和 600 帧采样窗口。
- 报告模拟工作平均时间与同步 GDI 绘制平均时间；诊断程序在 5 组、每组 120 帧后输出 CSV。诊断测量构建对对照和候选使用相同插桩。
- 功能冒烟与性能测试通过后，归档源码、脚本、二进制、ROM fixture、日志和 SHA-256 清单。
